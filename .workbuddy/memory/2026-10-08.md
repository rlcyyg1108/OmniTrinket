# 第二十四轮：面板底色回退 + 环境模块精简为两项（去掉权限门控）

## 1. ★ 面板底色回退（`drawVanillaPanel`）

**上一轮的错误做法**（已撤销）：
```java
graphics.blitNineSliced(AbstractWidget.WIDGETS_LOCATION, panelLeft, panelTop, w, h,
        20, 4, 200, 20, 0, 66);
```
`widgets.png` 本来就是**画按钮**用的贴图（边框只有 1~3px），9 宫格拉到 440×204
后视觉上就是一个"巨型按钮"。追求"跟随材质包"的思路本身对，但选错了素材
（1.20.1 里根本没有可当容器底板的原版贴图）。

**回退后的实现**（手绘原版容器配色）：
```java

private static final int COLOR_PANEL     = 0xFFC6C6C6;  // 浅灰底
// COLOR_HIGHLIGHT / COLOR_SHADOW 已有，滚动条也在用

graphics.fill(panelLeft - 1, panelTop - 1, panelRight + 1, panelBottom + 1, COLOR_OUTLINE);
graphics.fill(panelLeft, panelTop, panelRight, panelBottom, COLOR_PANEL);
graphics.fill(panelLeft, panelTop, panelRight, panelTop + 1, COLOR_HIGHLIGHT);     // 上高光
graphics.fill(panelLeft, panelTop, panelLeft + 1, panelBottom, COLOR_HIGHLIGHT);   // 左高光
graphics.fill(panelLeft, panelBottom - 1, panelRight, panelBottom, COLOR_SHADOW);  // 下阴影
graphics.fill(panelRight - 1, panelTop, panelRight, panelBottom, COLOR_SHADOW);    // 右阴影
```
★ `COLOR_PANEL` / `COLOR_OUTLINE` 是上一轮当"无用常量"删掉的，这次补回。
★ 材质包适配这条线**主动放弃**：手绘色块不会跟随材质包，但视觉正确。

## ★ 关键技术点：Component 参数样式优先

让"只有键位变紫、句子其余变绿"能生效的原理：
```
参数组件渲染时按  参数自身样式.applyTo(父样式)  合并，
Style.applyTo 里 this 优先 ⇒ 参数显式设过的字段压过父级。
```
所以做法就是把键名包成带颜色的组件当翻译参数传进去：
```java
private static Component key(Component keyName) {
    return keyName.copy().withStyle(ChatFormatting.DARK_PURPLE);
}
Component.translatable("tooltip.omnitrinket.flight.keyHint", key(KEY))
        .withStyle(ChatFormatting.GREEN);          // 父级绿 → 句子绿，参数紫胜出
```
（同理，死亡消息里玩家名保留队伍色就是这套机制。）

配套：`OmniTrinketItem.addFeatureTooltip` **不再**对 extra 行强制
`.withStyle(DARK_PURPLE)`（旧代码会盖掉键位色），改为直接 `tooltip.add(extra)`，
颜色由各功能自己在 `ClientTooltips` 里定。

# 第二十六轮：按键提示行补缩进 + 组合键的 "+" 也走键位色

用户反馈（tooltip 截图）：按键那两行要**首行缩进**（和其他描述行对齐），
「左Shift+右键」中间那个 `+` 没有染成键位色。

## 1. 按键提示行补 2 空格缩进
```json
"tooltip.omnitrinket.flight.keyHint": "  %s 键切换飞行速度档位（1/2/3/5/10）"
"tooltip.omnitrinket.buff.keyHint"  : "  %s 键切换夜视"
```
（与描述行 `"  双击跳跃开关飞行 / …"` 的 2 空格对齐。）
★ 注意：这与第二十五轮用户当时说的"没有首行缩进"相反 —— 需求已变更，以最新为准。

## 2. 组合键的 "+" 也染键位色

**问题**：lang 原为 `"%s+%s 或 %s 打开设置"`，`+` 属于外层字面量 ⇒ 跟着提示色变橙，
视觉上把"左Shift+右键"切断。

**修法**：把整段组合键**当作一个参数**，`+` 在参数内部构造：
```java
// lang 从 3 个占位符缩到 2 个："%s 或 %s 打开设置"
Component combo = key(mc.options.keyShift.getTranslatedKeyMessage())
        .append(Component.literal("+").withStyle(KEY_COLOR))
        .append(key(mc.options.keyUse.getTranslatedKeyMessage()));
return Component.translatable("tooltip.omnitrinket.hint.settings",
                combo, key(KeyBindings.OPEN_SETTINGS.getTranslatedKeyMessage()))
        .withStyle(HINT_COLOR, ChatFormatting.ITALIC);
```
★ 顺带把 `key(...)` 的返回类型从 `Component` 改成 **`MutableComponent`** ——
`Component` 没有 `append`，只有 `MutableComponent` 有。

# 第二十九轮（方案，未实施）：把除环境外的配置改成每玩家一份

用户要求：除环境外所有配置改为每人一份；**先只出方案**。

## 关键发现：项目里已经跑通了这个模式，只是只覆盖 4 个字段

| 组件 | 角色 |
|---|---|
| `PlayerSettings` | 服务端权威值（Forge Capability + NBT 持久化） |
| `ClientSettingsCache` | 客户端镜像（静态 CompoundTag） |
| `SyncPlayerSettingsPacket` | 服务端 → 客户端下发镜像 |
| `SetPlayerSettingsPacket` | 客户端 → 服务端改值（白名单 + clamp + 回发） |
| **`MoveSettings`** | ★ **双端取值器**：`player.level().isClientSide()` 分端读 |
| GUI `addPlayerToggle` / `sendField` | 已是每玩家写法 |

`MoveSettings` 的 javadoc 已经把根因写清楚了：
> capability 只在服务端被写入；客户端玩家那份永远是默认值，同步包只写 ClientSettingsCache。
> 所以凡是"客户端也要用到"的每玩家数据，必须分端取值。

要迁的就是**照这个模式再覆盖 15 个字段**（飞行 4 + 移动 3 + 生存 6 + 增益 2）。

## 5 个必须先定/注意的点（详见对话）
1. `TrinketFeature.isEnabled()` 没有玩家参数，而 tooltip(`appendHoverText`) 拿不到玩家
   ⇒ 接口要改成收一个 settings 视图；tooltip 走客户端镜像 + DistExecutor。
2. 客户端镜像靠 登录/换维度/重生 三个时机下发，够用；但要接受"镜像未到时用默认值"。
3. 环境保持全局是对的（`EnvironmentEvents.findOwner` 取第一个佩戴者，改成每玩家会变成"抢世界天气"）；
   但它的开关现在放在**全局 Config** 里却摆在 UI 上，多人服上改了不生效 —— 需二选一处理。
4. 改成每玩家后，X 键改的就是**自己**的值，HUD 直接读镜像 ⇒ 顺手修掉"HUD 用本机 toml 猜"的隐患。
5. 老存档：`PlayerSettings` 新增 15 个 NBT 键会回落默认值（原有做法），玩家之前调的值会回到默认；
   不做一次性迁移（代价 > 收益）。

## 落地顺序（每步可单独编译/验证）
1. `PlayerSettings` 改成"字段描述表"驱动（先只搬现有 5 个字段，行为不变）
2. `MoveSettings` 升级成通用 `PlayerSettingsAccess`（bool/dbl/int）+ 15 个字段进 NBT/白名单
3. 逐模块切读取点：飞行 → 移动 → 生存 → 增益
4. GUI 全切每玩家 + "重置全部"改成发一份含全部默认值的 patch
5. `Config` 只留 environment 两项，toml 同步
