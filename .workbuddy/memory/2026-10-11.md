## ★ 技术事实（本轮从字节码核实，别再猜）

- 1.20.1 的 `MobEffects.SATURATION` 就是**裸的 `InstantenousMobEffect`**，没有专门的类，
  补食逻辑写在 `MobEffect.applyEffectTick` 的**分支**里：
  `if (this == SATURATION && entity instanceof Player && !level.isClientSide) FoodData.eat(amplifier+1, 1.0F)`。
- `InstantenousMobEffect.isDurationEffectTick(duration, amplifier)` 返回 `duration >= 1`
  ⇒ 效果实例只要在列表里（时长 ≥1），**每个 tick** 都会触发补食
  ⇒ "每 5 秒续一次 20 秒" = 佩戴期间饱食度常满。（核验方法：javap 反编译
  `forge-1.20.1-47.4.10_mapped_official_1.20.1.jar` 的相关类字节码）

## ★ 未绑定键位的正确写法（已 javap 核实，别再猜）

```java
GLFW.GLFW_KEY_UNKNOWN   // = -1
```
- `InputConstants.UNKNOWN = Type.KEYSYM.getOrCreate(-1)`（静态块里就是这句）；
- `Type.getOrCreate(int)` 是 `map.computeIfAbsent(keyCode, …)` —— 按 keyCode 缓存，
  所以 KeyMapping 传 `-1` 拿到的**就是同一个 UNKNOWN 实例**；
- `KeyMapping.isUnbound()` = `key.equals(InputConstants.UNKNOWN)` → 直接成立，
  "控制"界面显示"未绑定"。标准写法：
  `new KeyMapping(name, KeyConflictContext.IN_GAME, InputConstants.Type.KEYSYM, GLFW.GLFW_KEY_UNKNOWN, CATEGORY)`。
