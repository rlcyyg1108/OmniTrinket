# 第二轮：参考 Better Controls 重构运动系统（A 撞墙恢复冲刺 / B 无惯性 / C 垂直倍率）

用户提供了 `参考资料/Better-Controls-1.20`（MC 1.20.5 分支），要求：

## 参考项目探明的关键事实（**对1.20.1 全部成立，已javap 验证**）

`Better-Controls-1.20`（1.20.5）与 `Better-Controls-main`（1.21.11）的最大差别：
**前者不用 MixinExtras**，全部退回原生注解 —— 这一点决定了我们能否照抄。

| 用途 | 1.21.11 版 | **1.20.5 版（我们照这个）** |
|---|---|---|
| 改方法返回值 | `@ModifyExpressionValue`（MixinExtras） | **`@Redirect`（原生）** |
| 改返回值并return | `@ModifyReturnValue`（MixinExtras） | **`@Inject` + `cir.setReturnValue`** |
| FOV | `@ModifyExpressionValue` | **`@Redirect`** |
| 依赖 | mixinextras-forge:0.4.1 | **无** |

### 1.20.1 字节码已验证的两个注入点（javap 核对）

**① 垂直飞行专用出口** —— `LocalPlayer.aiStep` 偏移 1122~1199：
```java
if (this.getAbilities().flying && this.isControlledCamera()) {
    int i = (this.input.shiftKeyDown ? -1 : 0) + (this.input.jumping ? 1 : 0);
    if (i != 0)
        this.setDeltaMovement(this.getDeltaMovement().add(
            0.0, (double)((float)i * this.getAbilities().getFlyingSpeed() * 3.0F), 0.0));
}
```
`getFlyingSpeed()` 在此处**只乘到 Y**（X/Z 补 0），且全方法内**只出现一次**（偏移 1186），
紧跟 `setDeltaMovement`（偏移 1199）⇒ `@Redirect` 无歧义，两个 `@Slice` 锚点成立。

**② 水平出口** —— `Player.getFlyingSpeed()` 是**另一个方法**，与上面完全独立。
**两个方法 = 两个出口 ⇒ 垂直倍率能真正单独调的根因。**

### 1.20.1 的 `Input` 类字段（与 1.20.5 分支源码一致）
```java
public float leftImpulse, forwardImpulse;
public boolean up, down, left, right, jumping, shiftKeyDown;
```
`LocalPlayer.input` 是 **public字段**，可直接读。
`AbstractClientPlayer.aiStep()` 在 1.20.1 **没有覆写**（字节码里是 `invokespecial`），
所以**不能拿它当 `@At` 锚点**（refmap 解析不到方法名 —— 项目踩过这个坑），
B 的 Mixin 改用 `@At("TAIL")`。

## ✅ A. 撞墙后恢复冲刺（新增功能）

`feature/impl/SprintResumeEvents.java`（纯客户端，`TickEvent.PlayerTickEvent(END)`）
+ `Config`：`resumeSprintAfterHittingObstacle`（默认 false）、`sprintResumeTicks`（默认 10）。

**关键坑**：`horizontalCollision` 在**松开方向键时也会变false**，
所以不能写成"撞墙就补"。必须三段式边缘检测：
```
① 撞上（false→true） ：记下wasSprintingBeforeObstacle（**必须保留到②被消费**，
   因为沿墙滑动时该状态会持续为 true）
② 离开（true→false）：若①记住了 → resumeTicks = 配置值
③ 倒计时期间：玩家自己按冲刺键 或 连前进键都松了 ⇒ 立即中止
```
倒计时递增逻辑用"逐帧递减"而非重置，这样长走廊撞一次墙能一路保持冲刺。

## ✅ B. 无惯性：清零 → 可调衰减（水平/垂直分离）

**删除** `feature/impl/NoInertiaEvents.java`。
**新增** `mixin/FlightInertiaMixin.java`：`@Mixin(LocalPlayer.class)` + `@At("TAIL")`。
**删除** `Config.flyNoInertia`，**新增** `flyHorizontalInertia` / `flyVerticalInertia`（0~1，默认 0）。

```java
if (in.forwardImpulse == 0F && in.leftImpulse == 0F) { s = sqrt(h); factorX = factorZ = s; }
if (!in.jumping && !in.shiftKeyDown)                { factorY = sqrt(v); }
```

三个改进点（相对旧实现）：
1. **时机**：从 TickEvent 迁到 `aiStep` 的 TAIL —— 移动已完全算完，不会"清了又动一点"
2. **可调**：清零（0/1 两档）→乘性衰减 `sqrt(m)`（0~1 连续），能表达"滑行一小段"
3. **水平/垂直分开**：旧实现只看水平判据、却把Y 也一起清 ⇒ 按住跳跃键上升时会被误判。
   现在两段独立判断。

`FlightSpeedHandler.noInertia()` → 换成 `horizontalInertia()` / `verticalInertia()`。

## ✅ C. 垂直倍率换注入点（★ 核心诉求）

**删除** `mixin/EntityMoveRelativeMixin.java`。
**新增** `mixin/LocalPlayerVerticalFlightSpeedMixin.java`：

```java
@Mixin(LocalPlayer.class)
public abstract class LocalPlayerVerticalFlightSpeedMixin {
    @Redirect(method = "aiStep",
        at = @At(value = "INVOKE", target = "Lnet/minecraft/world/entity/player/Abilities;getFlyingSpeed()F"),
        slice = @Slice(
            from = @At(value = "FIELD", target = "Lnet/minecraft/world/entity/player/Abilities;flying:Z"),
            to   = @At(value = "INVOKE", target = "Lnet/minecraft/client/player/LocalPlayer;setDeltaMovement(Lnet/minecraft/world/phys/Vec3;)V")))
    private float omnitrinket$applyVerticalMultiplier(Abilities abilities) {
        LocalPlayer me = (LocalPlayer) (Object) this;
        return abilities.getFlyingSpeed() * (float) FlightSpeedHandler.verticalMultiplier(me);
    }
}
```

**⚠️ `@Redirect` 接��的是"被调用的对象"（`Abilities`），不是返回值** —— 必须自己再调一次
`abilities.getFlyingSpeed()` 拿原值。这点与 `@ModifyExpressionValue` 的签名不同，是最容易写错的地方。

**为什么换**：旧实现打在 `Entity.moveRelative` —— 那是**所有**实体共用的出口
（走路/游泳/骑乘/鞘翅都走），在里面判条件开"带 if 的后门"既易与原版其它分支打架，
也拿不到"原版本来就要算垂直"这个语义。
